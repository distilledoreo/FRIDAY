# Cross-conversation continuity implementation

Goal: one consistent assistant with independent threads and selective, evidence-linked continuity. All archive, memory, situation and embedding storage stays on the PC. Phone storage contains its existing chats plus small settings; memory pages are bounded previews.

1. **Foundation** — Stream ChatGPT ZIP/JSON to authenticated PC API; select the visible branch; preview before committing; deduplicate without overwriting; CPU semantic plus full-text recall. Lasting facts require review with exact user quotes. Existing phone facts migrate only after server acceptance.
2. **Situations** — Extract up to four tentative, explicitly reported recent situations after a new completed chat. Keep source, quote, project scope, timestamp and open/resolved state separately from approved facts. Do not promote old imported archives into current life context.
3. **Updates** — Match existing situation IDs within scope, preserve up to twenty evidence-linked revisions, prefer newer statements, ignore repeated evidence. Open situations expire after thirty days, resolved after seven. UI can resolve or forget; forgetting excludes source recall. Approved facts can be edited without losing provenance; inferred contradictions remain reviewable rather than silently replacing user-approved knowledge.
4. **Per-turn context** — Retrieve relevant facts, archive excerpts, and up to three situations. Pinned communication preferences provide stable style guidance. Current instructions prevail. Greeting-only turns may receive one recent unresolved situation; unrelated specific questions receive none. All provided sources are inspectable.
5. **Check-ins** — Optional guidance only for relevant, unresolved situations from the last seven days; at most one offer per situation every three days. Count an offer conservatively when supplied, even if the model elects not to ask. Never assume the earlier mood persists. Disable with a separate setting. These are conversational replies, not scheduled notifications.
6. **Validation/delivery** — Test evidence rejection, unrelated misses, scopes, timestamps, resolution, repeated evidence, cooldown, expiry, settings, deletion, synthetic ZIP import, and CPU semantic retrieval; build Android and lint; deploy authenticated PC service; smoke test live extraction/recall; publish signed APK through existing private Tailscale download service.

Limits: automatic summaries are tentative and extraction may miss or misclassify statements. Exact quote validation establishes provenance, not the truth of an interpretation. No guarantee of ChatGPT parity. A real user export and physical phone layout require user testing. Retrieval and reconstruction do not change model weights or create human feelings.
